Overview

JsonMultiFileDataSource treats a directory of JSON files as a datasource, where each .json file becomes an independent entity — the rough equivalent of a table in an RDBMS. Each file carries its own inferred schema, its own data, and its own CRUD lifecycle.

It implements IDataSource and IDisposable, and is declared in the TheTechIdea.Beep.Json namespace.

How it differs from the other JSON datasources

ClassShapeDoc
JsonDataSource One file = one datasource (single entity) json-datasource.html
JsonDataSourceAdvanced Single file with richer querying/structure handling json-datasource.html
JsonMultiFileDataSource Directory = datasource, file = entity This page

Reach for this one when you have a folder of related JSON documents you want to query and join as if they were tables, rather than a single document you want to treat as one entity.

Directory Layout

The entity name is the file name without its extension:

/datasource/
    customers.json    -> entity "customers"
    orders.json       -> entity "orders"
    products.json     -> entity "products"

Each file may contain either a JSON array of records or a single JSON object. Schema is inferred from the file contents when the entity is loaded.

// customers.json - array form (multiple records)
[
  { "id": 1, "name": "Acme Corp",  "active": true  },
  { "id": 2, "name": "Globex Inc", "active": false }
]
// settings.json - single object form (one record)
{ "theme": "dark", "pageSize": 50 }

Registration & Connection

The class carries an [AddinAttribute], so AssemblyHandler discovers it during LoadAssemblies():

[AddinAttribute(Category = DatasourceCategory.FILES,
                DatasourceType = DataSourceType.JsonMultiFile)]
public class JsonMultiFileDataSource : IDataSource, IDisposable

Constructor

public JsonMultiFileDataSource(
    string datasourcename,
    IDMLogger logger,
    IDMEEditor pDMEEditor,
    DataSourceType databasetype,
    IErrorsInfo per)

The constructor looks up a matching ConnectionProperties by ConnectionName (case-insensitive) from DMEEditor.ConfigEditor.DataConnections and builds a FileConnection from it. Both directory-only and file + directory connection path patterns are supported, so a connection that names a specific file still resolves to its containing folder.

var conn = new ConnectionProperties
{
    ConnectionName = "catalog-json",
    FilePath       = @"C:\data\catalog",       // the directory of .json files
    DatabaseType   = DataSourceType.JsonMultiFile,
    Category       = DatasourceCategory.FILE
};
dmEditor.ConfigEditor.AddDataConnection(conn);

var ds = dmEditor.GetDataSource("catalog-json");

Connection Lifecycle

public ConnectionState Openconnection();
public ConnectionState Closeconnection();
public string DataDirectory { get; private set; }
public bool ObjectsCreated { get; }
public ConnectionState ConnectionStatus { get; set; }   // starts Closed

Openconnection() resolves DataDirectory and scans it for *.json files, populating EntitiesNames and Entities. DataDirectory is read-only from outside the class.

Close flushes. Closeconnection() is the point at which pending in-memory changes are written back to disk. See Persistence & Dirty Tracking — if the process exits without closing or explicitly saving, edits are lost.

Entity Management

public IEnumerable<string>  GetEntitesList();
public bool                 CheckEntityExist(string EntityName);
public int                  GetEntityIdx(string entityName);
public EntityStructure      GetEntityStructure(string EntityName, bool refresh);
public EntityStructure      GetEntityStructure(EntityStructure fnd, bool refresh = false);
public Type                 GetEntityType(string EntityName);

public IErrorsInfo          CreateEntities(List<EntityStructure> entities);
public bool                 CreateEntityAs(EntityStructure entity);

public void                 RefreshEntity(string entityName);
public EntityStructure?     AddEntityFile(string entityName, string filePath);

Two methods are specific to this datasource and have no equivalent on the single-file JSON providers:

  • RefreshEntity(entityName) — re-reads that one file from disk, discarding the cached copy. Use it when a file is modified by an external process.
  • AddEntityFile(entityName, filePath) — registers a JSON file that lives outside the datasource directory as an entity, returning the inferred EntityStructure (or null on failure).

GetEntityType() builds a runtime POCO type from the inferred structure, which is what lets UnitofWork<T> bind to these entities.

Relationships

public IEnumerable<ChildRelation>    GetChildTablesList(string tablename, string SchemaName, string Filterparamters);
public IEnumerable<RelationShipKeys> GetEntityforeignkeys(string entityname, string SchemaName);

JSON files carry no foreign-key metadata, so these return empty sequences. Model relationships in EntityStructure or a DataViewDataSource if you need joins across files.

Paging is supported through the PagedResult overload of GetEntity. UpdateEntities accepts an IProgress<PassedArgs> for bulk writes.

Per the BeepDM error convention, the write methods return IErrorsInfo rather than throwing — check Flag against Errors.Ok.

Persistence & Dirty Tracking

Edits are applied to an in-memory copy of the entity and flushed to disk explicitly:

public void SaveEntityToFile(string entityName);   // flush one entity
public void SaveAllDirtyEntities();                // flush everything modified
Writes are not automatically persisted per operation. InsertEntity / UpdateEntity / DeleteEntity mutate the cached entity and mark it dirty; the JSON file on disk is only rewritten when SaveEntityToFile, SaveAllDirtyEntities, or Closeconnection() runs. If the host process terminates without one of those, the changes are lost. Call SaveAllDirtyEntities() at a natural checkpoint, or dispose the datasource properly.

Unsupported Operations

Several IDataSource members exist only to satisfy the contract and are expression-bodied no-ops or failures — JSON files have no transaction log or SQL engine:

MemberBehaviour
BeginTransaction(PassedArgs)Not a real transaction
Commit(PassedArgs)Not a real transaction
EndTransaction(PassedArgs)Not a real transaction
ExecuteSql(string)No SQL engine
RunScript(ETLScriptDet)No script engine

GetCreateEntityScript(List<EntityStructure>? entities = null) is implemented and returns ETLScriptDet entries, so this datasource can act as an ETL/migration target — new entities become new files.

No atomicity across entities. Because transactions are no-ops, a multi-entity write that fails halfway leaves some files updated and others not. If you need all-or-nothing semantics, stage into a transactional datasource and copy across, or snapshot the directory first.

Gotchas

The runtime DatasourceType does not match the attribute. The [AddinAttribute] declares DatasourceType = DataSourceType.JsonMultiFile and Category = DatasourceCategory.FILES, but the constructor overwrites the instance properties with: 
DatasourceType = DataSourceType.Json;        // not JsonMultiFile
Category       = DatasourceCategory.FILE;    // not FILES
So discovery/registration sees JsonMultiFile/FILES, while code inspecting a live instance sees Json/FILE. Don't branch on ds.DatasourceType == DataSourceType.JsonMultiFile at runtime — it will not match. Test the concrete type instead: 
if (ds is JsonMultiFileDataSource multi) { /* ... */ }
  • The default property initialiser is also DataSourceType.Json, so the databasetype constructor argument is effectively ignored.
  • Files added to the directory after Openconnection() are not picked up automatically — call RefreshEntity, or reopen the connection.
  • Entity names are derived from file names, so they inherit whatever casing and characters the filesystem allows. Keep them simple if you intend to query them by name.

Usage Examples

Reading entities from a directory

var ds = dmEditor.GetDataSource("catalog-json");
ds.Openconnection();

foreach (var name in ds.GetEntitesList())
    Console.WriteLine($"entity: {name}");

var customers = ds.GetEntity("customers", null);
foreach (var row in customers)
    Console.WriteLine(row);

Filtering and paging

var filters = new List<AppFilter>
{
    new AppFilter { FieldName = "active", Operator = "=", FilterValue = "true" }
};

PagedResult page = ds.GetEntity("customers", filters, pageNumber: 1, pageSize: 25);

Insert, then persist

var result = ds.InsertEntity("customers", newCustomer);
if (result.Flag != Errors.Ok)
    dmEditor.AddLogMessage("App", $"Insert failed: {result.Message}",
                           DateTime.Now, 0, null, Errors.Failed);

// Nothing is on disk until this runs
((JsonMultiFileDataSource)ds).SaveAllDirtyEntities();

Attaching an out-of-directory file as an entity

var multi = (JsonMultiFileDataSource)ds;

var structure = multi.AddEntityFile("archive", @"D:\backups\archive-2025.json");
if (structure == null)
    Console.WriteLine("Could not load that file as an entity");

With UnitofWork

var uow = new UnitofWork<Customer>(dmEditor, "catalog-json", "customers");
uow.Get();

var c = uow.New();
c.Name = "New Client";
uow.Add(c);
uow.Commit();

// Still required - UnitofWork.Commit() does not flush the JSON files
((JsonMultiFileDataSource)dmEditor.GetDataSource("catalog-json")).SaveAllDirtyEntities();
