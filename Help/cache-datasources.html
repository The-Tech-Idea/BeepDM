Overview

Caching/DataSources/ provides IDataSource implementations that operate against an in-process cache instead of an external database. This lets BeepDM address a cache tier through the same contract used by SQL, file and API providers — so UnitofWork<T>, ETL and the sync engine can read and write it without knowing it is a cache.

Both classes live in the TheTechIdea.Beep.Caching namespace and share an almost identical surface. Internally each holds:

ConcurrentDictionary<string, ConcurrentDictionary<string, object>> _entityData;
ConcurrentDictionary<string, DateTime>                            _entityTimestamps;
ICacheProvider                                                     _cacheProvider;

— a per-entity keyed store plus timestamps, layered over an ICacheProvider.

Choosing between them

CachedMemoryDataSourceInMemoryCacheDataSource
DataSourceType DataSourceType.CachedMemory DataSourceType.InMemoryCache
Category DatasourceCategory.INMEMORY DatasourceCategory.INMEMORY
Provider (configured) MemoryCacheProvider(config) — Microsoft MemoryCache SimpleCacheProvider(config)
Provider (no config) SimpleCacheProvider() SimpleCacheProvider()
Expiration / size limits Yes — via MemoryCache policies No — lightweight, no eviction policy
Persistence None None
Intended for Production caching with policies and bounded memory Tests and local workloads

In short: use CachedMemoryDataSource when you want real eviction and size limits, and InMemoryCacheDataSource when you want a fast, dependency-free store for tests. If neither is given a CacheConfiguration, both fall back to the same SimpleCacheProvider and behave identically.

Registration

Both carry an [AddinAttribute] and are discovered by AssemblyHandler during LoadAssemblies():

[AddinAttribute(Category = DatasourceCategory.INMEMORY,
                DatasourceType = DataSourceType.CachedMemory)]
public class CachedMemoryDataSource : IDataSource

[AddinAttribute(Category = DatasourceCategory.INMEMORY,
                DatasourceType = DataSourceType.InMemoryCache)]
public class InMemoryCacheDataSource : IDataSource

Constructors

Each exposes a parameterless constructor and the standard five-argument datasource constructor:

public CachedMemoryDataSource();
public CachedMemoryDataSource(string datasourcename, IDMLogger logger,
                              IDMEEditor pDMEEditor, DataSourceType pDatasourceType,
                              IErrorsInfo per);

The parameterless overload exists for designer/DI activation; prefer the five-argument form, or resolve through dmEditor.GetDataSource(name) so the editor wires the logger and error object for you.

Connection Lifecycle

public ConnectionState Openconnection();
public ConnectionState Closeconnection();
public ConnectionState ConnectionStatus { get; set; }   // starts Closed
public void Dispose();

Openconnection() initialises the ICacheProvider — selecting MemoryCacheProvider or SimpleCacheProvider per the table above — and flips ConnectionStatus to Open. Dispose() releases the provider and nulls it.

Shared API Surface

Both classes implement the same members with the same signatures.

public bool                CheckEntityExist(string EntityName);
public int                 GetEntityIdx(string entityName);
public EntityStructure     GetEntityStructure(string EntityName, bool refresh);
public EntityStructure     GetEntityStructure(EntityStructure fnd, bool refresh = false);
public Type                GetEntityType(string EntityName);
public IErrorsInfo         CreateEntities(List<EntityStructure> entities);
public bool                CreateEntityAs(EntityStructure entity);

Reads

public IEnumerable<object> GetEntity(string EntityName, List<AppFilter> filter);
public PagedResult         GetEntity(string EntityName, List<AppFilter> filter,
                                     int pageNumber, int pageSize);
public Task<IEnumerable<object>> GetEntityAsync(string EntityName, List<AppFilter> Filter);
public IEnumerable<object> RunQuery(string qrystr);
public double              GetScalar(string query);
public Task<double>        GetScalarAsync(string query);

Writes

public IErrorsInfo InsertEntity(string EntityName, object InsertedData);
public IErrorsInfo UpdateEntity(string EntityName, object UploadDataRow);
public IErrorsInfo DeleteEntity(string EntityName, object UploadDataRow);
public IErrorsInfo UpdateEntities(string EntityName, object UploadData,
                                  IProgress<PassedArgs> progress);

Writes follow the BeepDM error convention — they return IErrorsInfo rather than throwing. Check Flag against Errors.Ok.

Filtering and paging behaviour is deliberately kept consistent with the other providers so callers can switch datasources without changing query code.

MemoryCacheConnection

Both datasources use MemoryCacheConnection as their IDataConnection adapter:

public class MemoryCacheConnection : IDataConnection
{
    public MemoryCacheConnection(IDMEEditor dMEEditor);

    public ConnectionDriversConfig DataSourceDriver   { get; set; }
    public IConnectionProperties   ConnectionProp     { get; set; }
    public ConnectionState         ConnectionStatus   { get; set; }   // Closed
    public IErrorsInfo             ErrorObject        { get; set; }
    public IDMLogger               Logger             { get; set; }
    public string                  GuidID             { get; set; }
    public bool                    InMemory           { get; set; }   // true

    public ConnectionState OpenConnection();
}
Two members throw NotImplementedException. MemoryCacheConnection.DMEEditor and MemoryCacheConnection.ID throw on both get and set: 
public IDMEEditor DMEEditor { get => throw new NotImplementedException();
                             set => throw new NotImplementedException(); }
public int ID              { get => throw new NotImplementedException();
                             set => throw new NotImplementedException(); }
Generic code that walks IDataConnection and touches either property will throw when it reaches a cache datasource. Guard with a type check, or read DMEEditor from the datasource itself (ds.DMEEditor) rather than from its connection.

Unsupported Operations

These members exist to satisfy IDataSource but a cache has no transaction log, SQL engine, or relational metadata:

MemberBehaviour
BeginTransaction(PassedArgs)Not a real transaction
EndTransaction(PassedArgs)Not a real transaction
Commit(PassedArgs)Not a real transaction
ExecuteSql(string)No SQL engine
RunScript(ETLScriptDet)No script engine
GetCreateEntityScript(...)No DDL to emit
GetChildTablesList(...)No relational metadata
GetEntityforeignkeys(...)No relational metadata

Gotchas

Nothing is persisted. Both datasources are process-local and in-memory. Restarting the host loses everything; there is no write-through to a backing store. Treat them as a cache tier, never as a system of record. If you need durability, sync to a real datasource (see BeepSyncManager).
  • No cross-process sharing. Two processes each get their own cache. For a shared tier use a Redis-backed provider through CacheManager, not these datasources.
  • Eviction is invisible to callers. With CachedMemoryDataSource and a configured MemoryCacheProvider, entries can disappear between two GetEntity calls. Don't assume a row you just inserted is still there.
  • Async methods are not truly async. GetEntityAsync and GetScalarAsync wrap synchronous work — they exist for contract parity. The folder README flags making them genuinely async as a future task, once I/O is introduced.
  • Distinguish these from InMemoryDataSource, which is a general-purpose in-memory provider rather than a cache-backed one.

Usage Examples

Registering a cache datasource

var conn = new ConnectionProperties
{
    ConnectionName = "hot-cache",
    DatabaseType   = DataSourceType.CachedMemory,
    Category       = DatasourceCategory.INMEMORY
};
dmEditor.ConfigEditor.AddDataConnection(conn);

var cache = dmEditor.GetDataSource("hot-cache");
cache.Openconnection();

Creating an entity and writing to it

var structure = new EntityStructure
{
    EntityName = "Products",
    Fields = new List<EntityField>
    {
        new EntityField { fieldname = "Id",   fieldtype = "System.Int32"  },
        new EntityField { fieldname = "Name", fieldtype = "System.String" }
    }
};

cache.CreateEntityAs(structure);

var result = cache.InsertEntity("Products", new { Id = 1, Name = "Widget" });
if (result.Flag != Errors.Ok)
    dmEditor.AddLogMessage("App", $"Cache insert failed: {result.Message}",
                           DateTime.Now, 0, null, Errors.Failed);

Reading with a filter

var filters = new List<AppFilter>
{
    new AppFilter { FieldName = "Name", Operator = "=", FilterValue = "Widget" }
};

var rows = cache.GetEntity("Products", filters);

// Paged
PagedResult page = cache.GetEntity("Products", filters, pageNumber: 1, pageSize: 50);

Warming the cache from a real datasource

var source = dmEditor.GetDataSource("northwind");
source.Openconnection();

var products = source.GetEntity("Products", null);

foreach (var p in products)
    cache.InsertEntity("Products", p);

// Reads now hit memory instead of the database
var cached = cache.GetEntity("Products", null);

Test double via InMemoryCacheDataSource

// No configuration -> SimpleCacheProvider, no eviction, fully deterministic
var testConn = new ConnectionProperties
{
    ConnectionName = "test-store",
    DatabaseType   = DataSourceType.InMemoryCache,
    Category       = DatasourceCategory.INMEMORY
};
dmEditor.ConfigEditor.AddDataConnection(testConn);

var uow = new UnitofWork<Product>(dmEditor, "test-store", "Products");
