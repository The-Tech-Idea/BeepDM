## Findings In Priority Order

### P1 - Reject replay can report recovery without a destination write

[DataImportManager.Replay.cs:113](../../DataManagementEngineStandard/Editor/Importing/DataImportManager.Replay.cs#L113)
returns true from an explicit write-integration stub. The caller then invokes
MarkReplayedAsync. A legacy store can therefore remove an unwritten reject from
pending work. Missing stores also return Ok at
[line 36](../../DataManagementEngineStandard/Editor/Importing/DataImportManager.Replay.cs#L36).
Both failures were reproduced by the existing recovery regressions in this pass.

Replay also resolves a slash-only context at
[line 136](../../DataManagementEngineStandard/Editor/Importing/DataImportManager.Replay.cs#L136),
while the current admission path uses `source/entity->destination/entity` at
[ImportQualityAdmission.cs:41](../../DataManagementEngineStandard/Editor/Importing/Quality/ImportQualityAdmission.cs#L41).
Current file-store edits introduce durable IDs/claims and refuse index-based
marking of managed records, but the replay manager does not consume that protocol.
These draft storage changes are not end-to-end recovery qualification.

Action: finish R14/P1-10/12 before exposing replay as successful recovery. Until
actual writes are integrated, fail closed rather than manufacture an acknowledgement.

### P1 - Sync promotion is neither staged nor bound to complete governed intent

[SchemaGovernance.cs:97](../../DataManagementEngineStandard/Editor/BeepSync/BeepSyncManager.SchemaGovernance.cs#L97)
changes the caller's version and mapping approval before two independent saves.
Failure of either save can leave memory, version artifacts and persisted schema
out of agreement. The promotion gate at
[line 62](../../DataManagementEngineStandard/Editor/BeepSync/BeepSyncManager.SchemaGovernance.cs#L62)
accepts null and arbitrary non-Boolean outputs unless their string is exactly
`false`; a missing engine/rule skips evaluation entirely.

[SchemaFingerprinter.cs:15](../../DataManagementEngineStandard/Editor/Schema/SchemaFingerprinter.cs#L15)
hashes connection/entity names, sync type/direction and field pairs, not the full
key/filter/policy intent. Null/failure paths fabricate a random identifier at
[line 39](../../DataManagementEngineStandard/Editor/Schema/SchemaFingerprinter.cs#L39).
This is not the corrected migration-plan hash contract.

Action: R13/remaining R12, P2-06/P3-07. Stage an owned candidate; require explicit
required/advisory gate semantics, versioned canonical intent and recoverable
publication. Do not promise a multi-file transaction from atomic individual saves.

### P1 - Migration checkpoint insertion does not own execution

[ExecutionOrchestration.cs:130](../../DataManagementEngineStandard/Editor/Migration/MigrationManager.ExecutionOrchestration.cs#L130)
checks Running before execution without atomic admission. Static concurrent
dictionaries protect lookup/insertion, not the subsequent shared step mutations.
Two callers can pass the initial check before either persists a Running step.
[GetExecutionCheckpoint:571](../../DataManagementEngineStandard/Editor/Migration/MigrationManager.ExecutionOrchestration.cs#L571)
also exposes the stored mutable checkpoint to callers.

Action: R02/P3-06. Introduce target/store/token execution ownership and return
owned progress snapshots. Qualify same-token and competing-token calls across
instances/processes. A process-local lock alone is not shared-store ownership.
This finding is source-derived; no new concurrency reproduction was run here.

### P1 - Remaining configuration facades hide failed saves and corrupt reads

[ComponentConfigManager.cs:243](../../DataManagementEngineStandard/ConfigUtil/Managers/ComponentConfigManager.cs#L243)
logs a workflow save exception and returns normally.
[Line 236](../../DataManagementEngineStandard/ConfigUtil/Managers/ComponentConfigManager.cs#L236)
replaces a failed workflow read with an empty collection; reports follow similar
patterns. A later save can treat unreadable state as fresh configuration.
The corrected connection and migration-history paths must not be generalized to
all other writers without evidence.

Action: R09/P2-05. Inventory each writer/reader, preserve corrupt bytes, propagate
acknowledgements through facades and coordinate the full read/modify/write cycle.

### P2 - Forms and plugin timers lack callback-generation ownership and drain

[TimerManager.cs:58](../../DataManagementEngineStandard/Editor/Forms/Helpers/TimerManager.cs#L58)
passes only a timer name to the callback. An old queued callback can resolve and
expire a replacement entry at
[line 90](../../DataManagementEngineStandard/Editor/Forms/Helpers/TimerManager.cs#L90).
CreateTimer does not reject creation after disposal; Timer.Dispose does not drain
already admitted callbacks. Plugin health monitoring similarly uses an async
timer callback at
[PluginHealthMonitor.cs:72](../../DataManagementEngineStandard/AssemblyHandler/PluginSystem/PluginHealthMonitor.cs#L72)
without an explicit task/drain owner.

Action: R07/P2-08/10. Add generation identity, explicit overlap policy, shutdown
admission and asynchronous drain where appropriate; define host/UI dispatch.

### P2 - NFEL can accept unmatched input and retain every parsed structure

At this review, [NfelParser.cs](../../DataManagementEngineStandard/Rules/BuiltinParsers/NfelParser.cs)
enumerated regex matches without checking gaps. Input such as `1 @ 2` left
unmatched characters without an error; final parenthesis balance alone did not
establish grammar validity. Each parse appended to an unbounded list (original
line 126). The subsequent [NFEL-1 implementation](../../DataManagementEngineStandard/Rules/NFEL.md)
corrects these boundaries; the original line anchors no longer describe current code.

Action: R08/P3-09/P4-07. Require complete token coverage, supported grammar and
input/depth/retention limits. Test malformed nesting and intentional dialect
differences. Parsing is not a sandbox for executable rule plugins.

### P2 - Import batch size does not bound source memory

[DataImportManager.cs:573](../../DataManagementEngineStandard/Editor/Importing/DataImportManager.cs#L573)
materializes the complete source before splitting batches. Increasing source
size therefore increases memory independently of configured batch size.

Action: R05/P4-01/02/03/04. Add optional paged/streamed provider capabilities and
bounded backpressure through reads, transforms, writes, retries and diagnostics.
Keep a documented legacy adapter; do not label synchronous calls interruptible.

### Immediate Change Boundaries

1. **Finish and qualify reject recovery (B1, R14/P1-10/12).** Use one canonical
   context plus durable run/reject identity. Persist operator preparation and an
   exclusive claim before any provider call. Rehydrate the already-transformed
   destination snapshot, bind actual target metadata/identity and re-evaluate
   current required quality policy without applying transformations twice.
   Acknowledge only a confirmed write. Preserve blocked claims after uncertain
   writes or failed completion persistence; require operator evidence to reconcile.
   Never infer a legacy payload stage or auto-release a claim by timeout.
2. **Qualify defaults/adapters (B1, R15/P3-09).** Distinguish absent defaults
   from failed catalog reads, sanitize resolver diagnostics and test custom helper
   contracts. Keep current required transformation and quality semantics intact.
3. **Stage promotion and cursor commit (B2, R13/R12/P2-06/P3-07).** Capture
   complete immutable governed intent, enforce strict promotion gates, and choose
   a documented publication/recovery protocol before implementation. Test every
   interruption point and competing publishers; publish live state only after
   the required durable acknowledgement. Row replay must not automatically mark
   a failed sync run Completed or advance its cursor.
4. **Deliver migration admission and remaining config contracts (D/C).** These
   independent lanes can proceed alongside B1. Define ownership across target,
   store and token, owned progress, crash reconciliation and version compatibility.
   Reuse established persistence primitives; do not hold storage locks across
   provider calls or user callbacks.
5. **Start provider/release evidence now; lifecycle/performance follow.** Inventory
   actual providers and select a small named reference set rather than claim all
   datasource enums are supported. Establish clean builds and API consumers in
   parallel. Streaming, native bulk and compensation rely on verified capabilities.

### Decisions And Merge Gates

Host integrators own authorization, reconciliation evidence, keys and UI dispatch;
the framework cannot authenticate an operator from a supplied display name.
Models/API ownership covers contract/version compatibility; subsystem ownership
covers runtime behavior/tests; release ownership covers OS/TFM/provider evidence.
Assign named people before estimating calendar dates.

Decide shared-store execution ownership, legacy-reader migration, supported
OS/TFM/provider versions, key rotation/export policy and retention budgets.
No universal exactly-once, transactional DDL, forced cancellation or power-loss
durability promise is inferred from these local tests.

Each increment must record the exact command, project/TFM counts, SDK/OS/provider,
fault-injection results and remaining limits. Restore a green source-built full
solution matrix before merge. Add restart/process and live-provider tests when
the claim concerns those boundaries. Update affected canonical `.cursor/<name>`,
harness and direct/nested installed Codex skills only to describe verified APIs.
Do not mark a broad phase complete from one helper fix or green mock-only slice.
